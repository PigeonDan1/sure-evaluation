# TTA — Text-to-Audio

TTA evaluates generated audio with FAD, FD, paired KL, Inception Score (IS),
CLAP score, and AudioBox Aesthetics CE/CU/PC/PQ.

## Prerequisites

Install SURE-EVALUATION from the repository and make sure `uv` is available on
`PATH`. The TTA node environments use Python 3.11; `uv` can install that Python
runtime automatically when it is not already present.

```bash
python -m pip install -e .
python -m pip install uv
```

## Prepare The Samples JSONL

The user creates this file from the audio generated by the system under
evaluation, the evaluation dataset's reference audio, and its text captions.
SURE-EVALUATION validates and consumes the file but does not generate it.

The file must be UTF-8 JSONL: one JSON object per line, no surrounding JSON
array, and no header row.

| Field | Required when | Meaning |
| --- | --- | --- |
| `sample_id` | Always | Unique stable identifier for one sample |
| `prediction_audio` | Always | Audio generated by the system being evaluated |
| `reference_audio` | FAD, FD, KL, or IS | Reference audio for distribution/paired metrics |
| `caption` | CLAP score | Text prompt or caption corresponding to the generated audio |

When using the all-metrics bundle, all four fields are required:

```jsonl
{"sample_id":"001","prediction_audio":"generated/001.wav","reference_audio":"reference/001.wav","caption":"A dog barking"}
{"sample_id":"002","prediction_audio":"generated/002.wav","reference_audio":"reference/002.wav","caption":"Rain falling on a metal roof"}
```

Audio paths may be absolute or relative. Relative paths are resolved against
the directory containing the samples JSONL, not the current shell directory.
Use at least two rows for an AudioLDM smoke test; distribution metrics need a
substantially larger representative set for meaningful scores.

## Run

```bash
sure-eval metric routes tta --metric fad

sure-eval metric describe tta \
  --metrics fad,fd,kl,is,clap_score,audiobox_ce,audiobox_cu,audiobox_pc,audiobox_pq \
  --output tta.json

sure-eval env setup --pipeline tta.json

sure-eval metric run \
  --pipeline tta.json \
  --samples-jsonl samples.jsonl \
  --output-dir results \
  --validate-env
```

The first `env setup` downloads the two pinned PANNs checkpoints, the pinned
LAION-CLAP checkpoint, the pinned AudioBox Aesthetics checkpoint, and the
pinned VGGish assets required by FAD (about 3.25 GB total), with progress and
checksum verification. For CLAP, setup also downloads only the four RoBERTa
configuration/tokenizer files used by scoring; it does not download BERT,
BART, or the RoBERTa base-model weights. Evaluation prefers these managed local
assets and uses the pinned upstream revisions only as a fallback when local
assets are unavailable. AudioBox loads the managed checkpoint directly; its
embedded model configuration means no separate Hub `config.json` is required.
Later setup calls safely reuse the existing node environments and downloaded
files. Use `--no-download` when preparing an offline environment, then populate
the declared checkpoint paths or set their environment-variable overrides.

FAD, FD, and KL are lower-is-better corpus metrics. IS, CLAP, and the four
AudioBox axes are higher-is-better metrics.
